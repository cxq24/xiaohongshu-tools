# 1.0.1 原生缓存与存档迁移

## 平台接口与范围

使用容器自动注入的 `window.xhs.miniTool`，不加载网络 SDK。客户端 9.46+ 且 `getStorage`、`setStorage` 均可用时使用原生缓存；普通浏览器或不支持该能力的旧客户端使用原浏览器存储。

版本从 `window.xhs.launchOptions.miniToolEnv.buildVersion` 读取，同步值缺失时调用 `getLaunchOptions`。按文档忽略末三位编译序号，例如 `9462004 → 9462`，与 `9460` 比较。

| 接口 | 参数 | 约定 |
| --- | --- | --- |
| getStorage | `{ key }` | Promise 返回 `{ data }`，data 为 JSON 字符串，缺失为 null |
| setStorage | `{ key, data }` | data 为 JSON 字符串；不传回调，等待 Promise 确认 |

原生缓存是设备本地数据，不是账号云存档。清除应用数据、卸载或换机不能保证恢复，也没有新增账号绑定／跨设备同步。

实现依据：小红书小工具扩展 `@skillbuilder/minitool-ai-extension@0.1.4-ci.20261113034101926` 随包 `js-api.md`（2026-09-23 快照）。该文档注明 Storage 为 9.46+、单 key 1MB／工具合计 10MB，读写需处理失败。当前线上规范仍以[平台文档](https://miniapp-sandbox.xiaohongshu.com/minitool/doc)为准；本次接口流程通过模拟原生桥验证，不声称完成小红书 iPhone 真机验收。

## 启动与迁移

- 关卡／星糖／外观／库存仍使用 `apu-candy-v1`，声音使用 `apu-audio-v2`。
- 先读取两个配置，再初始化声音、游戏和相关 UI。读取期间不会先写入一个默认空存档。
- 原生缓存已有有效数据时，以其为准，不与浏览器的金币、库存取最大值或合并。
- 原生缓存明确返回 null 且旧浏览器缓存仍可读时，迁移完整旧数据，再按原有规则正常化；旧存档的通关、已领取标记、消费和已解锁秘境一并保留。
- 只有不支持原生接口时直接使用浏览器存储。原生读取失败或数据损坏时，不把失败当作“没有数据”，不默认降级空进度，而是等待“重新读取”。
- 原生为空、旧缓存损坏／不可读时，可在玩家明确确认后开始新进度；确认后仍会重新检查原生数据，防止覆盖期间出现的有效存档。

迁移只能处理当前来源仍可访问的数据。已被清理或位于其他浏览器来源的旧 localStorage，无法凭空恢复。当前战斗仍不存档，关卡开始位置、通关与经济数据按原规则保存。

## 写入顺序与恢复

每次调用立即序列化独立快照；同一个 key 仅一个原生写入在途。期间产生的新状态会排队并合并为最新快照，不会让迟到的旧写入最后覆盖新星糖或库存。

浏览器可用时，先记录待同步日志再更新镜像，日志记录当前已确认值和在途值。若退出前没有收到确认，重开后仅在日志确实以当前原生值为前序时恢复最新快照；已提交相同值时不重复恢复。冲突时采用有效原生数据，不合并经济状态，并在浏览器可用时另留恢复备份。

已确认原生值保存在浏览器侧的 `:native` 元数据；待同步日志为 `:pending`，冲突备份为 `:recovery`。这些是本机恢复辅助，不是云备份，也不能替代原生写入成功确认。

原生写入超过 4 秒显示较慢提示，但保持写入锁直到真实调用结束；不会因超时再启动一个可能覆盖顺序的写入。读操作 4 秒超时后可重试。后台／页面离开时尝试提交待保存状态，但不能保证被系统强制终止前完成。

## 失败提示

正常保存不增加弹窗或诊断页面。只有失败或过慢时显示：

- 读取失败：等待重试，不启动空进度覆盖原数据。
- 写入失败：提示“进度保存未完成，请重试后再退出”，保留最新内存快照和可用的本机日志。
- 写入较慢：保持原请求，不允许第二个同 key 写入抢跑；成功后提示自动消失。

## 验证

`test_storage.cjs` 覆盖 14 组场景，包括迁移、版本门槛、异步启动、并发写入、失败／配额、日志重放、提交确认丢失、冲突、降级往返和浏览器存储不可用。

`native_storage_browser_checks.py` 从实际生产 ZIP，按文档形状模拟 `xhs.miniTool`，验证真实营地购买、声音设置、失败重试、重载恢复、启动不覆盖以及秘境可见性。模拟接口不等于原生客户端执行结果，发布前仍应在小红书预览中确认读写和重开。
