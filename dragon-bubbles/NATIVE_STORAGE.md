# 1.0.2 原生缓存与启动兼容

## 能力检测

使用容器自动注入的 `window.xhs.miniTool`，生产不下载或另行注入 SDK。检测 `getStorage`、`setStorage` 是否存在，并处理实际调用结果；不再要求启动信息带有客户端版本号，也不调用 `getLaunchOptions` 来阻塞读档。明确不支持原生能力时自动使用浏览器存储，无须用户查询版本或清除缓存。

旧接口文档标注 Storage 为 9.46+，该信息只作为参考，不作为启动硬门槛。版本号缺失不等于接口不可用；方法存在也不等于宿主实现了接口。无法承诺已测试每个历史客户端，但兼容按能力判断，无须逐个版本维护名单。

原生缓存是设备本地数据，不是账号云存档。清除应用数据、卸载或换机不能保证恢复。没有新增账号绑定／跨设备同步。

## 实际 SDK 返回兼容

调用同时兼容回调与 Promise，只发出一次请求，只处理一次结果。SDK 在传入 success／fail 后可能直接返回 undefined，异步回调才是调用结果。

| 场景 | 处理 |
| --- | --- |
| 启动元数据没有 buildVersion | 直接探测存储能力 |
| getStorage 成功但无 data、空字符串、null | 确认无该缓存后正常启动 |
| JSON 字符串、data 内对象、SDK 展开的存档对象 | 统一验证为 JSON 对象读取 |
| 明确 key 不存在，或 getStorageInfo 确认 key 不在列表 | 作为无存档处理 |
| 接口明确不支持（如 10002） | 自动使用浏览器兼容存储 |
| 主进度 I/O／权限／损坏或无法确认的读取错误 | 保留原档，提供重试与不保存试玩 |
| 仅声音偏好读取错误 | 不阻断有效游戏存档；使用可读的本机音量偏好，否则关闭声音等待用户设置 |

旧版 1.0.1 在“缺失版本信息”和“首次无缓存的成功空响应”下均可复现启动阻塞。回归使用 npm 发布的 `@skillbuilder/miniapp-simulator@0.2.12` 中真实 JS SDK 0.7.1，固定来源与哈希见 `tools/xhs-sdk-provenance.json`。该 SDK 会将原生 `{code:0}` 转成只有 `errMsg: getStorage:ok` 的返回，也会展开对象。宿主响应由测试模拟，不能据此确认用户手机当时走的是哪一个失败分支，更不等于 iPhone 真机验收。

参考平台接口文档仍见 [小红书文档](https://miniapp-sandbox.xiaohongshu.com/minitool/doc)。此前参考快照为小工具扩展 `@skillbuilder/minitool-ai-extension@0.1.4-ci.20261113034101926` 随包 `js-api.md`；本次通过发布 SDK 的实际转换行为补充兼容，测试参考 SDK 不进入生产 ZIP。

## 启动与迁移

- 关卡／星糖／外观／库存沿用 `apu-candy-v1`，声音沿用 `apu-audio-v2`，测试进度不导入生产。
- 先读取再初始化游戏，不先写一个默认空存档。原生有有效数据时以原生为准，不将星糖、库存取最大值或合并。
- 原生确认无存档且当前浏览器旧存档可读时迁移完整旧数据，保留通关、消费、已领取与秘境解锁。浏览器旧存储访问受限不会否定已确认的原生空缓存，也不会清理不可访问的数据。
- 可读取的旧缓存损坏时，仍需玩家确认开始新进度；确认后重新检查原生数据，防止覆盖期间出现的有效进度。
- 确实无法读取主存档时，“先试玩”只在内存运行，任何成长都不写原生或浏览器存储；提示持续显示“进度不保存”。“重新读档”确认结束试玩后重新加载。此入口不等同正常保存，不清理原档。

迁移仅处理当前来源可访问的数据；其他来源的 localStorage 或已被清理的进度无法凭空恢复。战斗中途仍不保存局面，关卡、通关与经济数据按既有规则保存。

## 写入与恢复

每次调用先序列化独立快照；同 key 仅一个写入在途，期间的修改合并为最新待保存快照。收到原生写入确认后更新已提交状态。原生写入失败不自动切换存储后端，以免形成相互覆盖的两个权威存档。

浏览器可用时先记录待同步日志，再更新镜像；日志记录已确认值与在途值。重开时只在最新日志确实以当前原生值为前序时恢复，冲突时采用原生，另留可用的恢复备份，不合并经济状态。

本机辅助键后缀为 `:native`（确认值）、`:pending`（待同步）和 `:recovery`（冲突备份）；它们不是云备份。原生写入超过 4 秒提示较慢，但一直保持锁到真实调用结束；不会超时后并发重写。读取 4 秒超时可重试。后台或离开时尝试提交，但无法保证系统强制终止前完成。

## 错误反馈与验证

正常游戏不显示诊断页面。仅异常时显示读取／保存提示；“复制错误信息”只含发布版本、存储模式、错误阶段、键名和错误码／原因，不包含玩家存档内容。该信息用于后续定位，不要求用户去设置里查询客户端版本。

`test_storage.cjs` 通过 20 组模型场景，涵盖迁移、回调／Promise、空缓存、对象返回、异步启动、串行写入、配额／错误、日志恢复和只读试玩。`test_sdk_storage.cjs` 与 `sdk_boot_browser_checks.py` 使用真实发布 SDK，复现旧包并从新生产 ZIP 验证启动、购买写入重载、自动兼容、音量故障隔离及原档保护。`native_storage_browser_checks.py` 另检查延迟启动、商店串行购买、失败重试、音量和秘境节点。真机请直接重新上传 1.0.2 后扫码验证，不必清缓存。
